**我的原始算法有误** ✗：TMDS 是 **10 bit/像素/通道** → `1.485Gbit/s ÷ 2(DDR) = **742.5 MHz**`（不是 371.25 ✗）。371.25 是 **720p** 的速率。

| 上限推算 | 结果 |
|---|---|
| 625MHz × 2 (DDR) | 1.25 Gbit/s/lane |
| → 最大像素时钟 | **125 MHz** |
| → 1080p 最高 | **≈50.5 Hz** → **1080p50 与 1080p60 均不可能** ✗ |

**时序（均 ≥0）**：1080p60 尝试：148.5MHz Setup **+1.690ns** / Hold **+0.424ns** / Fmax **198.263MHz**，0 违例。
**资源（1080p30）**：Logic 116/20736、BSRAM 0、rPLL 1/2 —— 约 0.5%，资源不是瓶颈。

### ⚠️ 三条必须记住的工具陷阱
1. **"编译通过 + 有 .fs" ≠ 成功** ✗ —— Gowin 对非法 PLL 只**告警并替换默认值**，仍会产出 .fs ✗（1080p60 的 .fs 就是这样生成的，**不可当 1080p60 用**）

**架构（经三次纠错后确认）**：
| 事实 | 值 |
|---|---|
| 强制位 | **$2000 bit 6 = 1**（EXT 输出/master）⚠️ 0 是输入 |
| 像素来源 | **EXT0~EXT3 = 14/15/16/17 脚**（4 位，非数据总线 ✗）|
| 缺的第 5 位 | 从 **VOUT（21 脚）** 用**比较器**提取 |
| 调色板 | **$2006/$2007 写监听 → 32×6bit 影子**（含 `$2000 bit2` 的 +1/+32 步长 ✓）|
| ⚠️ 安全 | **原机 EXT0~3 接地** → 必须先隔离再置 1，否则**烧 PPU** |

**仿真证据**：`EXT_OUT_BIT=2` 的对照实验**失败 11 项** ✓ → 反证 bit 6 才对 ✓
