# FC PPU Plus —— 项目角色章程

> 软硬件结合项目。四个角色，边界清晰，**测试独立于开发**。
> 共享状态全部落文档，任何角色/会话都能接手。

---

## 角色总览

| # | 角色 | 对用户 | 核心职责 | 主要工具 |
|---|---|---|---|---|
| 1 | **项目经理（PM）** | ✅ **唯一入口** | 接收任务、拆解、派工、跟踪、汇总、管理接口与风险 | todo / 文档 / 子代理调度 |
| 2 | **软件架构与开发** | 经 PM | Tang Nano 20K 固件与逻辑 | dsh-gowin（构建/约束/烧录/GAO） |

**铁律：角色 4 不由角色 2/3 兼任**，否则等于自己给自己判卷。

## 角色 1：项目经理（PM）

**职责**
- 接收用户任务 → 拆成可验收的工作项
- 判断归属角色、排依赖顺序（硬件接口先行 / 软件后跟）
- 维护**接口约定**（见下）与**风险清单**
- 汇总各角色产出，向用户**单一口径**回报
- 记录决策与理由（避免反复翻案，如 HDMI 落点已定案）

**边界**：不直接画图、不直接写代码；可以**审阅**并提出质疑。

**产出**：任务清单、接口表、进度汇总、决策记录、风险清单。

---

## 角色 2：软件架构与开发

**范围**（Tang Nano 20K：GW2AR-18 + BL616）
- USB → TF 卡读写（PC 经 J3/J4 的 Type-C 通路）
- HDMI 输出：**视频 + 音频混合**
- 编码器 A/B 解码 + **消抖**（由 BL616 做，不用 FPGA）
- OSD 同步显示
- 与拦截板的信号对接

**边界**：不碰 PCB 布线；严格按 PM 发布的**引脚定义**开发。

**产出**：RTL / 固件源码、约束文件（`.cst`/`.sdc`）、`.fs` 码流、接口说明、构建日志。

> 已知约束：Tang Nano 20K **只吃 5V**（板上自产 3.3V/2.5V/1.2V）；`TN_*` 信号电平以 3.3V 为准。

---

## 角色 3：硬件与电路开发

**范围**（尾板）
- 电源链：圆口 9V/1A（5–12V）→ F1/D1/C1 → **MP2315 → +5V**（**无 3.3V 轨**，由拦截板自降压）
- 反接保护：P-MOS（AO3407A + 10V 稳压管 + 10k）
- 接口：J5（电源/开关/主板 焊接落点）、J3+J4（升级口）、P1（板对板）、SW1（编码器）
- PCB：**器件全在顶层，底层整块地平面**

**边界**：不写 FPGA 逻辑；按 PM 发布的引脚定义设计。

**产出**：原理图（检查通过 + **逐网人工核对**）、PCB（DRC 通过）、BOM、装配说明。

> **已知教训**：EDA 检查的 `passed: true` **不等于网络有意义** —— 它只看「引脚有没有挂东西」，看不出网络是否通向别处。
> 必须额外做**逐网端点核对**（每个网络 ≥ 2 个端点）。

---

## 角色 4：测试与仿真

**职责**
| 类别 | 内容 |
|---|---|
| **仿真** | FPGA 逻辑仿真、时序分析（Setup/Hold 裕量） |
| **设计验证** | 原理图 ERC + **逐网端点核对**；PCB DRC；BOM 与丝印核对 |
| **在线测试** | GAO 逻辑分析仪抓波形；上板 bring-up；回归测试 |
| **缺陷管理** | 记录复现步骤 → 交回对应角色 |

**边界**：**不改设计**，只出报告与复现步骤。

**产出**：测试计划、用例、测试报告、缺陷单（含复现步骤）。

## 协作机制

```
用户
 │  任务 / 反馈
 ▼
PM（角色1）──── 单一入口
 │  任务单（含验收标准）
 ├──────────────► 软件（角色2）
 ├──────────────► 硬件（角色3）
 └──────────────► 测试（角色4）──► 缺陷报告 ──► 回流给开发角色
        ▲
        └── 各角色交付物 + 自检结果
```

**接口单一事实来源**：角色 2 与角色 3 靠**引脚定义**耦合。
该表必须有**唯一权威副本**，任何一方改引脚必须先经 PM 更新，不得各自为政。

## 已确认的运作方式（用户定）

1. **PM 暂时兼任硬件（角色 3）**
   - 理由：项目初期需求明确度高，由 PM 兼任效率最高
   - **后期按工作量再拆分**（届时硬件转独立子代理）

2. **角色可被用户直接点名，但 PM 必须参与**
   - 项目处于动态调整中，PM 需保持协调视角，不能因角色被点名而脱节
   - 做法：被点名的角色回答后，PM 需同步更新任务板与接口表（若涉及）

3. **验收标准逐步明确**
   - 不要求开工前写死全部判据
   - 但**每项任务推进过程中要逐步形成"怎么算做完"的表述**，并记入任务板
